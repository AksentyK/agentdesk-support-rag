# Дополнение к ТЗ Codex: утверждённые решения v1.1
Дата: 2026-10-30

Это дополнение имеет приоритет над неоднозначными формулировками версии 1.0.

## Продукт и разработка
Создаём не платформу AgentDesk, а демонстрационное приложение AI-техподдержки для вымышленного сервиса AgentDesk. Все изменения исходного кода выполняются в Codex. Приложение из приватного GitHub-репозитория разворачивается на Railway; локальный запуск тоже должен поддерживаться.

## Доступ
MVP без регистрации и личных кабинетов. Публичная временная ссылка защищается паролем DEMO_ACCESS_PASSWORD. На production все маршруты, которые расходуют RouterAI, требуют авторизации; также нужны ограничение частоты запросов и ограничения объёма тестов. Запросы не должны выдавать системные секреты.

## RouterAI и модели
Вся LLM-инференция через RouterAI с URL https://routerai.ru/api/v1.
Начальная пара моделей для тестирования (идентификаторы обязательно валидировать при запуске):
BASELINE_MODEL_ID=deepseek/deepseek-v4-flash
STRONG_MODEL_ID=anthropic/claude-sonnet-5.5
Они настраиваемы через env и валидируемую защищённую панель администратора; не зашивать в код. Если модель временно недоступна, показывать ошибку и предлагать выбрать другую модель из актуального списка RouterAI, без молчаливой замены экспериментального режима.

Для RAG-эмбеддингов разрешён отдельный локальный адаптер; нельзя молча использовать chat completion вместо embeddings. Требуется проверить размерность, протестировать индексирование и поиск.

## Эксперименты
Четыре режима: экономичная без RAG; экономичная с RAG; сильная без RAG; сильная с RAG. По умолчанию RAG включён. Измерять корректность относительно RAG_Test_Cases, полноту цитирования, отсутствие вымышленных фактов, время, usage и стоимость (если известна). Не считать сильную модель эталоном. Отделить тренировочную часть от holdout; holdout не использовать для улучшения промпта.

## Безопасность секретов
Пользователь передаст значения для заполнения `.env.local` или Railway Variables. Никогда не добавлять файл с реальными секретами в Git, PR, комментарии, логи, скриншоты или экспорт тестов. Зафиксировать .gitignore для .env, .env.*, с исключением .env.example. Проверить, что никакие ключи не уходят в клиентский JavaScript. Не запрашивать ключ в переписке.

## Railway
PostgreSQL + pgvector (выбрать образ или совместимое решение с поддержкой расширения). Выполнить миграции, initial KB import, health checks; обеспечить устойчивое постоянное хранилище. Деплой не считать завершённым до открывающегося URL, успешного авторизованного входа, RAG smoke test и рабочего сравнения двух моделей. Развёртывание, использование платного API и настройка секретов требуют отдельной настройки и проверки пользователем.

## План реализации в Codex
1) Создать репозиторий и базовый Next.js проект, зафиксировать зависимости.
2) Поднять PostgreSQL/pgvector, миграции и импорт Markdown KB (только один раз, без дублирования PDF).
3) Настроить embeddings, hybrid retrieval и корректные article_id citations.
4) Подключить RouterAI, две модели и 4 экспериментальных режима.
5) Сделать UI диалога и диагностики, тестовый стенд с результатами.
6) Защитить демо, выполнить unit/integration/e2e и проверить отсутствие секретов.
7) Развернуть на Railway и провести smoke test по публичному URL.

## Приёмка
Не менее 60 корректно загружаемых тестовых случаев; режимы переключаются без правки кода; цитаты указывают существующие AD-KB статьи; ответы при отсутствии источников корректно признают неопределённость; цена неизвестной модели обозначена как «нет данных», не 0; holdout изолирован; на Railway доступ по паролю и ни один секрет не доступен извне.
